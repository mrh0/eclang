# Compiler architecture

Paths are relative to `src/main/kotlin/github/mrh0/`.

## Data flow
```
.ec --ANTLR (EclangLexer/Parser + DenterHelper INDENT/DEDENT)--> parse tree
    --eclang/ast/Visitor.kt--> T* tokens (ITok)
    --ITok.process(cd, hint)--> (ect2.Type, IIR)   # type check + lowering, one pass
    --IIR.toC(sb, ctx)--> C text (CSourceBuilder + CTypes)
```

## Ecdocs: `eclang/doc/`
- The lexer (`@lexer::members` in `Eclang.g4`) sets every `/** ... */` (`ECDOC`) aside before the indentation tracking, keyed by the start offset of the next real token (`ecdocs`; `strayEcdocs` for those followed by another or by the end of the file). So the parser never sees them, and they can go anywhere.
- `Compiler.parse` returns the parse tree with the file's `FileDocs`: `DocExtractor` walks the top-level declarations of the tree (and record fields, interface members, enum values) and gives each the ecdoc before its first token. It builds a `DocItem` per declaration, with its signature from the source text (a function's is rebuilt as `fn name(params): R throws E`, so `declare fn` looks the same). `Ecdoc.parse` splits a comment into its Markdown description and tags. Problems (unknown tags, `@param` naming no parameter, unattached comments) become `DocProblem`s.
- `TProgram.docs` keeps each file's `FileDocs` (for tools such as a language server); the compiler reports their problems as warnings. `eclang doc` (`Main.doc`) only parses the files and renders them with `doc/Markdown.kt`.

## Types: `ect2/`
- `Type` is a sealed hierarchy: `Prim` (numbers, Bool, CString, String, Atom, Any, None, Never, Null, in `Types`), `Pointer`, `ArrayType` (`T[]`, `T[]c`), `Tuple`, `Union`, `FunctionType`, `Result` (`T throws E`), `IntLiteral`/`FloatLiteral` (untyped literals), `AtomLiteral`, `TypeParam` (`<T>`), `GenericRecord` (`rec List<T>`, a template, not a type of values), `Applied` (`List<T>` while an argument is still generic), and `Declared` = `Record` (nominal, `parent`, `externalName`/`isExternal`/`isCStruct`; an instance such as `List<Int>` has `generic` and `typeArgs`) | `Interface` (structural).
- `TypeContext` (one per compilation, in `CompileData.types`) creates types and interns them, so equality is `===` and `id` is a dense cache key. `union()` normalizes: it flattens, deduplicates, drops `Never`, lets `Any` absorb everything, drops subsumed members, and sorts by id.
- `cost(from, to)` is the single compatibility rule, cached per id pair. It returns 0 when `from` already is a `to` (same type, union member, record parent, interface), 1+ for a lossless conversion (smaller is closer), and `NO` otherwise. `accepts`, `isSubtype`, union normalization and overload resolution all build on it. Number conversions are only lossless widenings. Literals fit any type that holds the value exactly, preferring Int. Composite types (arrays, tuples, function types) must match exactly, because their C layout depends on them, so a tuple literal gets its conversions from the expected type (`TCreateTuple`).
- `explain(from, to)` gives the human reason plus a fix. `storageProblem(t)` reports types that can't be stored (`Any`, interfaces, `<T>`, `Result`). `concrete(t)` gives a literal its default type (Int/Long/Double). `bind`/`substitute` handle generics; `apply` gives a generic record's instance, made once per type arguments by `TTypeRecord.instantiate` in the record's module.
- `ect2/Test.kt` holds the unit tests (`java -cp target/eclang-0.1.0.jar github.mrh0.ect2.TestKt`).

## AST tokens: `eclang/ast/`
- `Visitor` has one `visitX` per labelled grammar alternative. Parsed-but-unsupported syntax throws "not supported yet".
- `Tok(location) : ITok`. `process(cd, hint)` returns the type and IR. Statements return `Types.None`.
- Shared rules: `ast/token/op/Ops.kt` (`common` type of two operands, `arithmetic` with constant folding of literals, `comparison`, `nullComparison`, `requireBool`, `shortCircuitRight`), `statement/Defines.kt` (`defineValue`), `statement/Returns.kt` (`returnWithDefers`), `data/Arrays.kt`, `data/record/Records.kt`, `type/Declarations.kt`.
- **Assignment** (`statement/TStatementAssign.kt`): a plain name is handled directly (it ends narrowing). Any other target must implement `IAssignable` (`ast/IAssignable.kt`: `TNamed`, `TAccessorNamed`, `TAccessor`, `TReadPointer`), whose `place` returns a `Place`: the type, a C lvalue IR, and `readOnly`, the full error when it can't be changed. Field places inherit `readOnly` from their base unless they go through a pointer, which is how a field of a `val` record is rejected. `x op= v` is emitted as C's compound operator; on a narrowed name it uses the narrowed lvalue (`x.v.m0 += 1`).
- **Built-in functions** (`function/call/Builtins.kt`): `format`, `concat`, `clone`, `keep`, `hash`, `newPool`, `clearPool`, `freePool`, used only when no function of that name is visible (`hash` also when none of them takes the argument). Those that allocate take an optional pool (first, or second for `clone`) and otherwise use the current pool. `keep(x)` clones into the pool current when the function was called (`cd.entryPool`: the `__ec_parentN` of the outermost `pool do` block, or the pool around the outermost loop whose rounds get a pool, decided when the C is written, `LoopPools.IREntryPool`); it stands in the call's pools as a `TEntryPool`, which Lifetimes counts as `#pool` and never as local memory. A String literal with `${...}` is a `TInterpolated` (the Visitor splits it with `StringLiteral.splitInterpolation` and parses each expression with `Compiler.parseInterpolation`, the `interpolation` grammar rule); it is built in the current pool, like `format("...")`. That becomes `IRFormat`, a call of a generated `__ec_format_N` helper (`CTypes.format`) that uses `snprintf` twice and `__ec_palloc`.
- Type declarations implement `ITypeDeclaration` (`declareType`, then `defineType`), so records can reference each other in any order.

## CompileData: `eclang/context/CompileData.kt`
- Holds `types`, `functions`, the current `function` (an `Overload`), the scopes (`ctx()`), `genericContext` (name → bound type in a generic instance), the current `module`, and the loop stack.
- `expect(loc, value, to, what)`: checks with `cost` and returns the IR wrapped in `IRConvert(IMPLICIT)` when a conversion is needed. It throws `EcTypeMismatchError` with `explain`.
- `storable` checks a type can be stored and returns it concrete; `usable` rejects `None` and `Result`; `lookupType` adds "did you mean" suggestions.
- **Evaluation order:** `ArgumentOrder` makes arguments, `${...}` parts, operator sides and the values of literals run left to right. An assignment whose target and value both call something keeps the target's address in a temporary first (`TStatementAssign.pinned`). `cd.effects` counts the calls compiled (`cd.noteEffect`), so comparing it around a value tells whether that value runs code; only what a later value could affect goes into a temporary. Temporaries are hoisted statements when nothing ran earlier in the statement (`cd.nothingRanInStatement`) or a later value hoisted something (they go in front of it with `cd.hoistAt`), and otherwise are set in a comma expression around the call.
- **Hoisting:** `hoist(loc, ir)` adds a statement before the current one (used by `try` and by `??` on a `Result`). `TBlock` wraps each statement in `collectHoisted`. Code that may not run, or runs repeatedly (`and`/`or` right sides, `else if`, `while` conditions, inline `if`, `defer`), uses `noHoist(reason)`. `TTailIf` collects its body's hoists inside its own `if`.

## Modules: `eclang/context/Module.kt`
- `TProgram.collect` gives each top-level declaration the module of its file (`module "name"`, or `cd.topLevel`, named ""). Every phase compiles a declaration inside `cd.inModule(m)`, and `Functions.build` compiles a body inside its overload's module.
- Lookup of an unqualified name: locals, then the current module, then the top level (`cd.findVar`, `cd.visibleModules()`); for types `TypeContext.lookup(namespace, name)` (namespace, then "", then "core"). A name found only in another module gives the hint "write `geo.name`" (`cd.whereElse`).
- Qualified names: `geo.make(…)` is a method-style `TExprCall` whose receiver names a module (and no variable); `geo.origin` is `TAccessorNamed` the same way; types and record literals pass "geo.Point" to `cd.lookupType`; `fn geo.make` is `TNamedFunction(qualifier)`.
- C names: `Module.cName` for functions and globals, `Declared.cName` for records (`geo__Point`). `cd.claimCName` rejects two definitions that end up with the same C name, and prefixes a global whose name C's headers already use with `__ec_v_` (records get an error instead). Locals and parameters use `cd.localCName`, which does the same when the name would hide a file-scope name (a C function, a generated `log_6`, a global). Globals whose initializer isn't a C constant (`IIR.isConstant`) are assigned at the start of the C `main` (`IRGlobalDefine.toCInit`).
- `use "x.ec"` resolves next to the using file (inside `core:` for bundled files), then in the working directory (`Util.resolveUse`). Files are deduplicated by canonical path.

## Functions: `eclang/context/function/Functions.kt`
- `declare(TFunc)` expands each function into `Overload`s, one per combination of union-parameter members (`variants`: atoms stay together, `T?` stays one, a nullable union adds a `Null` variant) and present/absent default parameters. Duplicates are errors. C names are `name_N`, or the extern name.
- Parameters typed `<T>`, an interface (or a pointer to one, `@Named`) or `Any` (in non-external functions), a `<T>` in the return type or a generic variadic make an overload a **template**. Each call calls `instantiate`, which compiles a copy for the argument and result types (`name_N_gK`). A `<T>` only the result has comes from the call's expected type; `TExprCall` compiles lambdas without parameter or return types last (`TLambda.wantsExpectedType`), with the types `lambdaHint` works out from the other arguments.
- Overloads are stored per module. `call(loc, name, args, qualifier)` takes the visible ones (the current module's and the top level's, or only the qualifier's), scores each with `cost` (templates pay a penalty), picks the lowest, and reports ties as ambiguous (a concrete function beats a template, the current module beats the top level). It converts the arguments and handles typed and C varargs. Errors explain the closest candidate.
- Calls of `declare fn` functions bridge C's `const`: arguments that are pointers to pointers or function pointers are cast to `void*`, and pointer results to eclang's C type (`IRCCast`).
- `TExprCall` first tries, in order: a qualified call, a function-typed field of the receiver (`b.onClick(x)`), a variable of function type (`f(x)`, `IRCallValue`), and then overload resolution.
- `buildAll()` is a worklist: each body is compiled once, and an error in one is reported (`cd.recover`) before the next is built. Missing `ret` on a path is an error. `isUnionCopy` marks per-type copies. More than `MANY_COPIES` (16) copies of one function give a warning.
- `use(cName)` records a call graph (from `call`, `reference` and `lambda`, keyed by the C name of the function or lambda being compiled, or `ROOT` for globals). `reachable(main, irs)` drops the C functions nothing reaches, typically unused union copies; they were still type-checked.
- Lambdas (`TLambda`, `fn (x: Int) = x + 1`) are compiled where they appear, inside `cd.isolated` (a fresh scope with no loops, hoisting or `cd.function`) and `cd.inClosure` (a `Closure`), and become C functions named after the function around them (`main_0_lambda0`, `Functions.lambda`); `buildAll` returns them after the bodies.
- Closures: a function value (`FunctionType` without `isC`) is in C a pointer to a struct whose first member is the C function, `struct __ec_closure_M { R (*call)(void*, A); }` (`CTypes.closureStruct`), called with the closure first: `f->call(f, x)`, or `__ec_call_M(...)` when the callee isn't a plain name (`IRCallValue`, `CTypes.closureCall`). So a function value is still one pointer: null, unions and `!as` work as before. A lambda's C function takes `void* __ec_self` first. When `cd.findVar` doesn't find a name in the lambda's scope, `CompileData.capture` looks in the function around it (`outside`, recursively through nested lambdas): a `val` or parameter is copied (with its narrowed type) into the closure and read as `__ec_env->x`, a `var` is shared through a pointer (`(*__ec_env->x)`). A local `const` is just its value. The lambda's value is `IRClosure`: `(&__ec_value_id)`, a static closure, when it captured nothing, or `__ec_new_id(limit, &count)`, which allocates a `__ec_env_id` in the current pool (both written by `IRFunctionOverride.toCDeclaration` from its `ClosureC`). For Lifetimes, `TLambda.captured` holds `x` or `addrof x` per capture, and the closure is current-pool memory when it captured something (`Lifetimes.value`/`sources`/`allocations`); closures hold pointers (`holdsPointer`). A call of a function value may return what its closure points to (`TExprCall.aliased` includes the callee). Names a lambda body may change (`mut x`, `addrof x`, `x.f()`, from the Visitor: `Closure.changes`) are, once captured, forgotten by narrowing and added to `cd.changedByClosures` and `changedByCalls`.
- `fn name` as a function value is a static closure of a C function that calls it (`Functions.closureOf`, `__ec_ref_f_0`).
- C function pointers: in a `declare` and in an `export fn`, function types are `TypeContext.inC` (`isC`, `extern (A) => R` in errors, the C typedef `__ec_cfn_M`). `TLambda` and `TNamedFunction` with such a hint give the C function itself; a lambda that then captures something is an error. The two kinds never convert to each other (`explain` says how).
- `try` in a lambda: `TTry` uses `cd.closure` when there is no `cd.function`. The lambda throws its written or expected `throws`, or else the union of what its `try`s can fail with (`Closure.thrown`); `IRTryPropagate` gets the lambda's result type lazily (`Closure.result`), as it is known only after the body. Where the expected function type returns `None`, a lambda's value is dropped; `Functions.lambdaHint` leaves a still-generic return type open as `Any`.
- `x |> stage` (`TPipe`): the visitor counts the `it`s in each stage and rewrites a stage without `it` (`f(2)` → `f(it, 2)`, `f` → `f(it)`, a lambda → `TCallValue`). `TPipe` pushes the value on `cd.pipeValues`, which `TIt` reads; a value used more than once is hoisted into a temporary first unless it's a variable or literal.

## Flow typing: `eclang/context/Narrowing.kt` + `ContextStack`
- `Narrowing.of(cd, condition, whenTrue)` returns name → narrower type for `x == null`/`!= null`, `x is T`, `!!x`, and `not`/`and`/`or` combinations, for local names only.
- `ContextStack.Scope.narrowed` is copied into child scopes. `getRaw` returns a `NarrowedVar`, which reads through `IRConvert(NARROW)`. Assignment calls `forget`.
- `TStatementIf`, `TTailIf`, `TInlineIf`, `TStatementWhile`, `for ... where`, `assert`, `requires` and `and`/`or` apply narrowings. After an `if` whose bodies all leave (`Scope.returned`, which also covers break/continue), the false-narrowings apply to the rest of the block.
- `Narrowing.constant` decides checks at compile time, only inside union copies. The dead branch is skipped, and code after an always-taken leaving branch is skipped (`returnedStatically`) instead of being reported as unreachable.

## `mut` parameters and `ref rec`
A `mut p: T` parameter has the type `@T` and is a `T*` in C. The Visitor rewrites every `p` of the body to `@p` (a `TReadPointer` with `mutParameter`), so the rest of the compiler sees an ordinary pointer parameter: assignments are writes through it, and Lifetimes checks what is stored there as stored behind a parameter. Only three things know about `mut`: `Lifetimes.place` (the function can't keep `addrof p`), narrowing (kept under the key `@p`), and calls. A call compiles `mut x` (`TMutArg`) as `&x` after checking x is a place that can change, and `Functions.score` matches it to a `mut` parameter of exactly its type; a method receiver goes by address when only a `mut` first parameter takes it. As the callee can't keep the pointer, the caller only has to follow what the callee may store in x: the call's other arguments and its pools (`TExprCall.followChanges`).

A `ref rec` is an ordinary `Record` with `Layout.isRef`. Only name resolution changes: in a type, the name is a pointer to it. So everything a pointer to a record can do (fields through it, `extends`, `is`, `clone`, printing, `T?` as a plain pointer) works unchanged, and a recursive `ref rec` is finite.

## Pools and lifetimes
- `Pool` is a built-in type, `TypeContext.pool` = `@apr_pool_t` (the `apr_pool_t` record is in the `core` namespace, so `apr/pools.ec` doesn't declare it). The current pool is the C thread-local `__ec_pool` (runtime prelude in `IRProgram`), created by the C `main` before the global initializers. `pool` in code is `TNamed` falling back to it when no variable has that name (`TNamed.isCurrentPool`); `pool` is not a keyword.
- `pool do` / `pool name do` (`TStatementPool`, grammar `keyword=NAME name=NAME? 'do'`, checked in the Visitor) pushes a scope, saves the current pool in a `__ec_parentN` temp, and defers an `IRPoolLeave` (destroy, then restore), so every exit frees the pool through the usual defer machinery. `IRPoolBlock` writes the C block.
- `new` (`op/TNew`, `IRNew`): `new value` calls `__ec_new_<T>(pool, v)`; `new T` passes `CTypes.zero(T)`; `new T[n]` calls `__ec_alloc_<A>(pool, n)`. A `TNamed` (or `module.Name`) that is a type and not a variable is read as a type.
- `${x}` of a record or tuple (`IRShow`, `CTypes.show`) generates `__ec_show_<T>` helpers that return a String, each built from a `format` helper. A pointer goes through `__ec_show_enter`/`leave`, which print `...` for a cycle or past 32 pointers, and dispatches on `__ec_tid` like `clone`. `Functions.resolvePrinters` finds the program's `str` functions at each `${...}`, and the helpers call them (`callPrinter`).
- `hash(x)` of a type without a `hash` function (`IRHash`, `CTypes.hash`) mixes the fields in `__ec_hash_<T>` helpers, over the types `equalityProblem` allows.
- `clone` (`IRClone`, `CTypes.clone`) generates `__ec_clone_<T>` helpers per type (every helper gets a prototype, in `helperFunctions`, so they can call each other in any order). A pointer to an extended record dispatches on `__ec_tid`. Types that hold no copyable memory (`ownsMemory`) are returned as is. Pointer clones look up and record each copy in a map (`cloneRuntime`: `__ec_clone_enter`/`put`/`leave`, made in a scratch pool by the outermost clone), so cycles and shared values are copied once. The map's key is the address and a `cloneKind`, as a record and its first field share an address; a hierarchy and a `distinct` type with its base are one kind, so that their pointers stay shared; `__ec_clone_root_<T>` holds one map for a whole array or record.
- Record field defaults are kept in `cd.recordDefaults` (set by `TTypeRecord.defineType`); `createRecord` compiles a missing field's default inside `cd.isolated`.
- Interfaces with `fn` members: `cd.interfaceMethods`; `Functions.score` rejects a record for an interface parameter when `missingMethod` finds a function it lacks.
- `priv` declarations: `TProgram` records them in `Module.privateFunctions`/`privateGlobals`/`privateTypes`; `Functions.visible`, `cd.findVar`, `cd.getVarIn` and `cd.lookupType` hide them from other modules.
- **Lifetimes** (`context/Lifetimes.kt`): `value(cd, tok)` is the `Local` memory (a scope depth plus wording) a value may point into, found from the tokens just compiled: `addrof` of a local place, array literals, record literals, `new`, calls (`TExprCall.pools`: pool arguments, and the current pool for eclang functions and allocating builtins), `"${...}"`, and the pass-through operators. Variables remember it (`ContextStack.setOrigin`, set by the `val`/`var` definitions and assignments). A `Local` with `holder` is an array's storage: an element read from it (`TAccessor`, `for`) gets `Local.stored()`, what the elements point into. `addrof` of a literal is a `temporary`, the `...rest` parameter a holder (`defineRest`), and `usesStack` finds an array literal in a record field's default. `checkReturn` (`ret`, `throw`, lambda results) rejects any `Local`; `assign` (from `TStatementAssign`) rejects a value whose memory is freed before the target's scope ends (a global or a place behind a pointer outlives the function). `pointees` is the local variables a value may point at (`ContextStack.addPointees`), so that a store through a pointer changes them. Only types for which `holdsPointer` is true are checked. Inside a `pool do` block, `cd.poolBlocks` holds the blocks' `Local`s, so allocations in the current pool get the innermost block's lifetime, and `TTry` copies a propagated error into `cd.poolEntry` (`IRTryPropagate.copyInto`).

- **Through calls** (`context/Escapes.kt`): while a body is compiled, `Lifetimes.assign` records each store through a parameter or into a global as an `Escapes.Store` of that body (shared by generic instances and union copies), in terms of its parameters: `Lifetimes.sources` is what a value may point into (parameter names, `#pool` for the caller's pool, `#global`, `p[]` for p's elements), `pointeeSources` only what a pointer points at (`new R { c }` is in the pool, not in c; a call's result points into the arguments in its `storedInto`, those whose type can reach what it points at, see `Lifetimes.storedInto`). Locals remember both (`Escapes.addLocal`, by name, flow-insensitive). `TExprCall` records each call of an eclang function (`Lifetimes.noteCall`) with each argument's `Local` and sources. Callees are often compiled after their callers (generic instances always are), so `Escapes.check` runs after `buildAll`: it passes stores on to callers until nothing changes, then checks every call as if the store were written there. Calls inside `unsafe` aren't checked. An `escaping` parameter is a `Store` into `#global` with `escaping = true`, recorded when the function is declared, which `message` words as "outlives the call"; `Lifetimes.checkEscaping` checks at the call what `Escapes` can't: a C function's local memory, and a pool the caller owns. A `kept` parameter of a `declare fn` (`TParameterKept`) is a `Store` into each other pointer parameter, recorded under the `Overload` (it has no body), so its calls are noted like an eclang function's. Interface methods need nothing: an interface parameter makes a template, whose copies call the concrete function.
- **Lambdas and function values** (`Escapes`, keys are `Any`: a `TBlock`, a `Closure`, an `Overload` or a `FunctionType`): a lambda's stores are its own (`Lifetimes.escapeScope`, `Escapes.inLambda` for its locals), in terms of `Closure.escapeParams`: its parameters, and `^x` / `^x*` for each capture (the value of a `val`, the place and the value of a `var`; `Lifetimes.captureSource`). `Lifetimes.noteLambda` records, where the lambda is written, a `Call` of it given each capture (`Call.lambda`), which checks what it keeps of the function around it; a store into its own parameter counts as a global there. What a lambda or `fn name` (`TNamedFunction`) keeps of its own parameters, or of `#pool`, goes to its `FunctionType`'s stores by position (`%0`, `Escapes.addToType`) when it is kept in another parameter or `escaping`; `Lifetimes.noteValueCall` (from `TExprCall.callValue` and `TCallValue`) records each call of a function value as a call of that type. Kept anywhere else (a capture, a global) it is an error (`keptElsewhere`), unless the value was made inside `unsafe`.
- **What results point into** (`Escapes.resultRoots`): `Lifetimes.noteResult` (from `checkReturn` for `ret` and `throw`, and `TTry`) records what each function gives its caller, by `Escapes.key` (location and types of the overload, which stays the same between compilations, unlike C names). `Functions.build` marks it complete unless the body had errors, took a local's address or has a lambda that changes a `var` (`startResult`/`finishResult`); `computedResults` closes it over the function's stores behind what it returns, after passing stores on. `Compiler.compileHere` compiles again with `knownResults` when a compilation fails with an `EcMemoryError` and found something new (at most `MAX_PASSES`); `TExprCall` then keeps in `aliased` only the arguments the callee returns into (not with `mut` arguments, whose changes `followChanges` follows through `aliased`). Each argument kept remembers its parameter (`aliasedParams`, `calleeKey`), so that `Lifetimes.allocations` tags memory that came through calls with `Alloc.via`; `checkLeaving` hands such memory, which a deferred free would free under a `ret`, to `Escapes.leaving`, and `Escapes.check` reports it when every call on the way returns into what it was given. `Escapes.storeOrigins` remembers why a caller got a store from a callee, so an error at a call names the calls in between (`chain`).
- **Threads** (`context/Sharing.kt`): an argument of a `flat` parameter must reach no memory but `sync` records (`Sharing.problem`); for a pointer parameter that is what it points at, for a lambda what it captures (`TLambda.captures`, with no `var` shared). Checked in `TExprCall.noteCall`, not inside `unsafe`.

## Freed pools
- `Lifetimes.allocations(cd, tok)` is the set of `Alloc`s (a named pool, a sequence point) a value may be in, followed like `value` (`flows`). Variables keep theirs in `ContextStack.Scope.allocations`; `define` and `assign` set them (a field or memory assignment adds to the base variable's).
- `own p: Pool` (`TParameterOwn`, `Parameter.isOwn`): the callee's `ownedPools` start with p's pool (`Functions.build`); at the call, `Lifetimes.giveAway` requires a pool the caller owns (or `unsafe`) and `kill`s it with `free`, so the caller can't use it or its memory afterwards.
- `clearPool(p)` (`Builtins`) and `destroy p` (`TStatementDestroy`) call `Lifetimes.kill`, which records a `Kill` for p's pool in the current scope; `TNamed.process`/`place` call `checkAlive`, which rejects a variable with an `Alloc` older than its pool's kill, or a pool freed with `destroy`. `ContextStack.pop` joins a scope's kills and allocations with its parent's unless the scope always left (so `defer destroy p` run at an early `ret` doesn't count after the `if`). `ContextStack.join` takes several paths: the latest kill of each pool, the union of each variable's `Alloc`s, and an `Alloc` that no path holding it freed gets a new sequence point (after every kill so far), so that the merged kills don't make it look freed. `pop(ran = true)` (a block's own scope, `TBlock`) replaces the parent's knowledge; `TStatementIf` takes `popBranch` of each branch and of the "no branch/else" scope and `joinBranches` them, without the state before the `if`. Loops rely on `LoopRound` (below) for what a later round sees.
- Pool identity: `Scope.pools` maps a pool variable, a global or a `Pool` field (`h.p`, from `Lifetimes.path`) to its pool (`val q = p` shares it, `p = new Pool` makes a new one, `trackPools` walks a record's fields). `Lifetimes.poolId` is the pool of a value. The current pool is the block's (`Local.pool`) or `CALLER_POOL`; those and `blockPools` are what `destroy` rejects, and `clearPool` rejects `CALLER_POOL` and a pool with a running block inside it (`Builtins.destroyProblem`, `clearProblem`); `unsafe` doesn't allow these. Without `unsafe`, both need a pool the function owns (`Lifetimes.owns`): one in `ownedPools`, which `trackPools` fills for a place given `new Pool` (or null, or an `if` of those), or for `clearPool` a block's pool. On a `Pool?` place, `destroy` also compiles an assignment of null (`TStatementAssign`), after `kill`, so the place gets a new pool identity. `setPoolParents` records who a pool is a child of: `ContextStack.kill` frees the children too.
- A way out of a scope compiles its deferred statements in `ContextStack.onExit`, so what they free counts on that way out only. `returnWithDefers` checks the value there (`Lifetimes.leaving` before, `checkLeaving` inside); `viaCall` allocations don't count, see KNOWN_ISSUES. `TTry` copies the error when `onExit` says a pool is freed.
- Globals keep their allocations too (the names `Scope.vars` doesn't have), and `Lifetimes.kill` rejects freeing what one holds.

## Loops
A loop's body is compiled once, in source order, but runs again on what it left. `cd.forgetAssigned` starts a `LoopRound`, `CompileData.loop` ends it (`Lifetimes.loopCompiled`, `loopLeft`).
- Local memory is flow-insensitive, so it can simply run again: `Lifetimes.followed` makes a step (`define`, `assign`, `checkReturn`) and records it as a `Replay` with its scopes. When the outermost loop has been compiled, `replay` runs them until `ContextStack.followed()` settles. A `define` replaces what is known (`resetOrigin`), so a variable defined in the loop starts over. A step must only read and write what is followed: allocation tracking uses sequence numbers, so it stays out of it.
- **A pool per round** (`context/LoopPools.kt`): a loop outside `pool do` blocks (in a function, not a lambda) allocates in a pool that outlives it; when nothing a round allocates outlives the round, its rounds get a pool, as if the body were in `pool do`. `CompileData.loop` pushes a `LoopPools.Loop` on `cd.loopPools` (its round starts at the scope its body opens, `cd.roundLoops` lists them all) and sets `ContextStack.pendingRound`, so that pushing that scope defers a `RoundLeave` there (every way out of a round frees it); `compileLoop` wraps the body in `IRRound`. Both write nothing unless `Loop.enabled`, which `LoopPools.decide` sets after `Escapes.check`. `TTry` copies an error it passes on into the entry pool when a round's pool may be freed on the way out. `unsafe` code counts as keeping what it is given there (`Escapes.check`'s imagined calls, `checkEscaping`). and `followed` runs each step a second time with `ContextStack.imagining` set, as if a `pool do` were around the body: `Lifetimes.currentPoolMemory` is then `LoopPools.memory`, a `Local` with `loopPools`, and variables use `imaginedOrigins` (outside imagined steps, writes go to both maps). Where a real `Local` would be an error (`checkStore`, `checkReturn`, `checkEscaping`, and `Escapes.check` for the imagined calls), round memory instead marks the loops it would outlive `kept`, and anything else an imagined step throws is dropped, so errors and the real analysis are unchanged. The allocating forms call `cd.noteAllocation` (`Builtins.current(cd, ...)`, `${...}`, `new`, and `TExprCall` for eclang functions, which count once `LoopPools.warn` has worked out which functions allocate in their caller's pool, and for C functions given that pool). After `Escapes.check`, `LoopPools.decide` enables the innermost loop around each allocation that nothing kept.
- Pools are flow-sensitive, so replaying won't do. Every variable gets an `Alloc` with `carried` at the start of the loop, which an assignment replaces. A use that sees it (`checkAlive`) may see the previous round's value, so it becomes a `CarriedRead`. `checkCarried` compares those with the `RoundEnd`s, at the end of the body and at each `continue` (`roundEnds`), also for the pools freed before the read in the same round. `PoolRead` does the same for a pool the loop frees.

## `when`
- `TStatementWhen` (grammar `statementWhen`, `whenArm`) desugars to `TStatementIf` on `x is T` / `x == v` (`WhenOn`). A non-name subject goes into a C temporary (`Fixed`); `when val n = e` defines n in a block. Without `else`, `WhenOn.missing` checks a union (or Bool) subject is covered, using `Overload.declaredUnions` for split union parameters; the last arm then becomes the `else`.

- A guard makes `WhenArm.guard`, and `n if c do` also `WhenArm.binding`: n is an `InlineConstant` for the subject, defined by `Bound` around the condition and around the body. A range value (`TRange`, whose ends may be null) is `x >= a and x < b`.
- `TWhenExpr` (`when` as a value, grammar `whenExpr`) wraps each arm's value in a statement setting a temporary and compiles a `TStatementWhen` with `exhaustive`. The type is decided after all arms are compiled, so the temporary's type is a lambda (`IRTempDeclare`) and each assignment's value is set late (`IRWhenAssign`). The chain is hoisted, so it isn't allowed under `noHoist`.
- A `when` ends with a DEDENT, after which the denter gives no NL, so statements take a `tail` (`expr NL | whenExpr`) instead of `expr NL`. An expression that merely ends in a `when` needs parentheses.

## Temporaries in expressions
`cd.declareTemp` hoists only a declaration, and the value is set in place with `IRTempSet`: `a < (tmp = f()) && tmp < c`. So unlike `cd.hoist` it works under `noHoist`, keeps evaluation order and doesn't evaluate what is skipped. It is used for the middle of a chained comparison (`TChainFirst`, built by `Visitor.chain`), the receiver of `q?.f()` (`TSafeCall`) and the base of `{ ...p }` (`TUpdateRecord`). Deferred statements go through `cd.compileDeferred`, which gives each its own temporaries, as it may be compiled once per exit.

## Never
- `Types.Never` as a return type: `Functions.declare` allows it, `build` requires the body to diverge, and C gets `_Noreturn` (`IRFunctionOverride`). `TStatementCall` and `TStatement` call `setReturned` on a Never value, so flow typing and the missing-`ret` check see it like `ret`. `ret` of a Never value is just the call.
- It fits any type (`cost` 0); as a value in C it is `(call, zero)` (`CTypes.convert`). A call through a function value is followed by `__builtin_unreachable()`, which C can't work out itself.

## Tuples
- `(a, b)` is `TCreateTuple`, `(A, B)` in a type is `TTypeTuple`, both giving a `Tuple`. Without an expected type, parts take their stored type (an atom an `Atom`, so `(:ok, 1)` fits `(Atom, Int)`). In C it is a struct with fields `first`, `second`, ... (`CTypes.tupleField`, `Util.getTupleEntryName`), read by `TAccessorNamed`.
- `TDestructure` (`val (a, b) = v`, `var (a, b) = v`, `(a, b) = v`) has no IR of its own: the value goes into a hidden local (`hiddenName`, a name no source can spell), and each part is an ordinary `TStatementDefineVal`, `TStatementDefineVar` or `TStatementAssign` of `hidden.first`, so lifetimes, flow typing and the `val` rules need nothing new. `destructured` flattens a pattern into targets and reads. A pattern of names is a `TCreateTuple` of `TNamed` (`Visitor.destructure`); the parser reads `(a, b) = v` as an assignment to a tuple expression, which the Visitor turns into a `TDestructure`. Lifetimes follow the whole value, so a part counts as pointing where any part may.
- `for (a, b) in values` (`TStatementForeachIn.pattern`) does the same with a hidden loop variable.
- `mangle` gives a type its id instead of a name another type already has, since `(Int, (Int, Int))` and `((Int, Int), Int)` read the same.

## Iteration
`TStatementForeachIn.loopOver` decides what a `for` loops over, in this order: an array or String (`overElements`); a type with `next(@X)` (`iterator`, `overIterator`); what `iter(x)` gives, which goes through `loopOver` again. `for a, b in x` first tries `pairs(x)`, and then a and b are a pattern (`TCreateTuple` of two `TNamed`), so the rest is `for (a, b) in`.
- `Functions.protocolCall` resolves these calls: what is visible from here, then the module that declares the type (`owner`), like `str`, because the value may come from anywhere. `x.name(...)` and `Functions.missingMethod` do the same, through `Functions.methodModule` and `owners`, which also tries the modules of a record's parents.
- The iterator goes into a temporary before the loop. `next` is called at the top of the body, in `for (;;)` (`IRStatementForeachNext`), which is what lets `continue` work and keeps its plain `break` from skipping `else` (a source `break` is a `goto` there).
- `<T>?` flattens, so a generic `next` with `T` nullable returns the same type as `T`. `iterator` rejects that (`Overload.bindings`), as the first null would end the loop silently. `List`'s `iter` gives a slice, so a `List<Int?>` works and its loop is the array loop.
- Loop variables of `next`, `iter` and `pairs` loops get their memory from the iterable (`Lifetimes.define`), since a call's result may point into its arguments; those over an array written after `in` get what the array's elements point into (`element = true`).

## Fixed-size arrays
- `FixedArray` (`T[N]`) is a C struct with one array member, `__ec_fixed_Int_4 { int data[4]; }`, so C can assign and return it: tuples work the same way. `TTypeFixedArray` reads N through `compileTimeInt`.
- A record field of this type is a plain C array (`int d[4];`), as C code and `declare struct` expect. `readField` wraps the access in `IRFixedStorage`, which casts the array to the struct: `(*(W*)x.d)`, still an lvalue, with the same bytes. `CTypes.member` does the same in generated helpers, and `DeclaredConstant` for a C global. Anything that reads a record's fields in C must go through one of those.
- `IRCreateRecord` writes an array literal as `.d = {1, 2}`. C can't initialise an array from a value, so any other value goes through `__ec_set_R__d` (`CTypes.setFixed`) after the literal.
- `a[i]` (`IRAccessorFixed`) and `.data` use the C array directly when `a` is an `IRFixedStorage`, except for arrays of arrays, where the struct's view and C's differ.
- Nothing converts to `T[]` implicitly: a conversion is invisible to `Lifetimes`, which follows tokens. `a[..]` and `.data` set `viewsValue` on their token, and `Lifetimes.value` then adds the `place` of the array; `TAccessor.inValue` makes `place` and `localRoot` treat an element as part of the array.
- `TProgram.earlyConstants` compiles constants first, so types can use them; one needing a declared type waits for the phase of the globals.

## Record layout
- `Record.layout` (`Layout`: `packed`, `align`, `isUnion`) and `Record.bitWidths` are read by `CTypes.complete`. They come from `TLayout` and `fieldWidth` in the grammar. `packed`, `align`, `union`, `struct`, `export`, `extern` and `module` aren't keywords, so the grammar takes a `NAME` and the Visitor checks the word; `SyntaxHints.startsTopLevelStatement` keeps the top-level hint working now that a declaration can start with a name (`declarationWords`).
- Inside a `packed` record `unaligned` is set on `TAccessorNamed`/`TAccessor`. `addrof`, `a[..]` and `.data` reject it unless `alignedAnywhere`. A whole array is read through the typedef `W_u` (`aligned(1)`, `CTypes.storage`), so gcc reads it safely.
- `IRCheckedCompound` normally takes the target's address, which a bit-field or packed field doesn't have: `noPointer` writes `t = helper(t, ...)` instead, and `TStatementAssign.repeatable` rejects a target with calls in it.
- `CTypes.allocate` calls `__ec_palloc_aligned` for a type whose `align(n)` exceeds the 8 bytes pools give.

## Exports and libraries
- `export fn` sets `TFunc.exportName`, which becomes the C name (`Overload.exportName`, claimed with `claimCName`). `Functions.checkExport` rejects what would compile to several C functions. Exported functions are roots of `Functions.reachable`.
- With `cd.library` set, `TProgram` needs no `main`, and `IRProgram` writes `libraryEntry` instead: a constructor running what `main` runs first, with the globals in `__ec_globals`, and a destructor. Other C functions are `static` (`CTypes.isHidden`).
- Exported functions start with `__ec_enter()`, which gives a thread entering from C a pool. `NAME_clear` clears the calling thread's.
- `IRProgram.header` uses a `CTypes` of its own, so its definitions are exactly what the exported signatures need. A signature with a type from a C header (`usesCTypes`) includes every `use`d header, as which one declares it isn't known.

## Named arguments
`TExprCall.argNames` runs alongside the arguments after the receiver. `Functions.call` asks `arrange` to put them in each candidate's parameter order; arguments in order must fill `Overload.declared` from the start. Leaving out parameters needs no new code, since each combination of defaults already is an overload. When two combinations have the same types (`f(a: Int = 0, b: Int = 0)`), the later one is `namedOnly`: `f(1)` means a.

## Distinct types
`Distinct` (`type X = distinct T`) is a `Type` of its own with a `base`, a C typedef written with the forward declarations (`CTypes.distinctName`). `cost` only lets number literals in, at a slightly higher cost than the base. `Ops.isNumeric`/`isInteger` look through it and `Ops.base` gives what a value is underneath, for code that needs a `Prim`, so arithmetic stays on the distinct type. `comparison`, `CTypes.convert`, clone and field or element access unwrap it.

## Runtime checks
- `RuntimeChecks.needed` (in `Ops.kt`) decides when `/ % << >>` (and with `--overflow-check` `+ - *`) on whole numbers become `IRCheckedArith`/`IRCheckedCompound`, calling `CTypes.checkedArith` helpers (`__ec_div_Int(a, b, "f.ec:3")`).
- `TExprCall` wraps pointer results of `declare fn` calls in `IRCNotNull` (`__ec_c_nn`). `Functions.cVarArgProblem` rejects structs passed to a C `...`.

## Assertions, `debug` and contracts
- `assert`, `requires` and `ensures` all compile through `Assertions.compile` (`ast/token/statement/Assertions.kt`): `a and b` becomes one check per part (the later ones under `noHoist`, each narrowing the next), comparison and `is` operands that run code go into `IRTempDefine` temporaries read back through `TValue`, and the report is a `TInterpolated` built by hand and compiled with `Builtins.interpolate` in the current pool without `noteAllocation`, so it is only made on the failure path (`IRAssert` → `__ec_panic_text`). The Visitor records the source text of each expression token of a condition (`withSources`, by identity) for the report. An unprintable union shows its member (`IRHeldType`, `CTypes.heldType`). A check decided by the types (`Narrowing.decided`) or constants (`ir/ConstFold`) warns or fails, except in union copies and generic instances.
- `debug stmt` / `debug do` (`TDebug`) is a `TStatementIf` on `TDebug.Flag` (`IRDebugFlag`, C `__EC_DEBUG`, defined by `CTypes.useDebugFlag` from `--release`). Being an `if` with an unknown condition keeps names, narrowings, pools and lifetimes sound in both builds. `ContextStack.debugDefined`/`debugNarrowed` add hints to the errors about relying on them. `debug defer x` is `defer (debug x)` (Visitor). `debug` isn't a keyword: `statementPrefixed` is `NAME statement`, last in `statement`, and `debug do` reuses `statementPool`.
- `const assert` (`TConstAssert`): conditions are folded by `ConstFold` (`InC` for `sizeof` & co., emitted as `IRStaticAssert`); `A is/fits B` use `TypeContext.cost`, record distance and `Functions.missingMethod`; `outlives` and `in` ask `Lifetimes.outlivesProblem`/`inPoolProblem`; `not escapes(p)` is an `Escapes.Claim` checked in `Escapes.check` after stores are propagated. `Overload.calledAt` names the call that made a generic instance.
- Contracts (`Contract`, on `TFunc.contracts` and `Overload.contracts`, copied to instances): `Functions.build` starts a function with `requires` with `IRTakeCallSite` (`const char* __ec_at = __ec_take_call_site("decl")`), then the defaults, then the `requires` checks reported at `__ec_at`. A direct call (`callIR`) goes through `Functions.contractCall`'s `f_0_at(args..., "file:line")`, which sets the thread-local `__ec_call_site` after the arguments ran and calls `f_0`; function values and C call `f_0`, which then reports at its own place. `ensures` are compiled by `Functions.ensures` with `result` bound to a temporary, in `TStatementReturn` and at the end of a function returning None.

## Errors as values
- `fn f(): T throws E` returns `Result(T, E)`. `TExprCall` returns that type, and only four things accept it: `try` (`TTry`, which hoists `IRTryPropagate`: on error it runs the defers and returns the error converted to the outer function's error type), `??` (a hoisted temp plus `IRInlineIf`), `try … catch e do` (`TStatementTryCatch` → `IRTryCatch`), and `if val x = f() do` (`TStatementLetIf`, a hoisted temp tested with `.code == 0`; the same token handles nullable values).
- `throw`/`ret` in a throwing function build `IRResultValue`. A `None throws E` function gets an implicit success return at its end.

## C output: `eclang/output/c/`
- `CTypes` is the only place that knows the representation:
  - Primitives map to C directly.
  - `T?` of a pointer-like type, and unions of atoms, are plain pointers that may be NULL.
  - Other unions are `struct { int tag; union { … } v; }`, with the tag being the member index.
  - Arrays (`{size_t len; T* data}`), tuples and results are generated structs.
  - Records are structs. A child holds its parent as its first member, named like the parent (`struct Dog { Animal Animal; bool good; }`), so an inherited field is `d.Animal.legs` (`CTypes.fieldPath`; `parentMember` adds `__ec_` when a field has the parent's name). C allows a pointer to a struct to be used as a pointer to its first member, so `(Animal*)d` and the checked downcast are valid C, and gcc's `-O2` sees that an `@Dog` and an `@Animal` may point to the same memory. The top record of an `extends` hierarchy starts with `__ec_tid` (the record id), so every record of it does (`CTypes.tagPath`).
  - Function types are typedefs.
- Names are readable mangles (`__ec_union_Int_CString`). Types are forward-declared, and definitions are completed in dependency order (`definitions()`).
- `convert`/`narrow`/`isCheck` produce C expressions. Checked conversions (union → member, `x!`, downcasts) call generated `static inline` helpers that `__ec_panic("file:line", msg)` on failure.
- `a[i]` on arrays and Strings calls `__ec_at_<type>` (`CTypes.elementAt`), which checks the bounds and returns a pointer, so `(*__ec_at_AInt(a, i, "f.ec:3"))` is still an lvalue; `cd.boundsChecks` (`--no-bounds-check`) turns it into `a.data[i]`. Slices (`a[x..<y]`, `TRange` inside `TAccessor`) call `__ec_slice_<type>`. Record `==` calls `__ec_eq_<record>` (`CTypes.recordEquals`); `equalityProblem` in `Ops.kt` decides which field types it supports.
- `x?.field` calls a generated `__ec_safe_<type>__<field>` helper (`CTypes.safeAccess`), so `x` is evaluated once without hoisting.
- `"${x:spec}"`: `FormatSpec.split` separates the expression, the `x=` label and the format, finding the `:` by what comes before it (an atom follows an operator or a space). `FormatSpec.apply` checks it against the value's type and gives the printf conversion and C arguments.
- `errdefer` (`TErrDefer`) adds a deferred statement that `TErrDefer.normal` filters out at every exit but `throw` (`returnWithDefers(error = true)`) and `try`.
- Loops with an `else` block (`compileLoop` in `ast/token/loop/Loops.kt`) emit the block after the loop; a `break` then becomes `goto __ec_loop_endN` (`cd.loop`, `cd.breakLabel`), and the label is only written when used. So does `break outer` (a loop's label comes from `ILabeledLoop`), and `continue outer` becomes `goto __ec_loop_nextN`, a label at the end of the body, after its deferred statements. `break` and `continue` first run the statements deferred inside the body of the loop they leave (`cd.loopDeferred`), and a loop forgets the narrowing of every variable its body assigns (`cd.forgetAssigned`, names collected by the `Visitor`) before compiling its condition and body.
- Bitwise operators (`TBitwise`, `IRBitwise`) are always parenthesized in C, because C's `&`/`|`/`^` bind looser than `==`.
- `--check-memory` (`cd.checkMemory`, `CTypes.checkMemory`): `IRProgram.checkedRuntime` makes `__ec_palloc` a `malloc` per allocation, freed by a cleanup of its pool, and `IRBlock.lineOf` writes a `#line` before each statement (and in `IRPoolLeave`, `RoundLeave`), so that AddressSanitizer reports eclang lines. `run -m` builds with `-fsanitize=address`.
- `IRProgram` renders the code before the type definitions and helpers. The runtime prelude has `__ec_string_t`, `__ec_panic` (`_Noreturn`), `__ec_panic_index`/`__ec_panic_slice`, `__ec_nn`, `__ec_str_eq` and `__ec_str_concat` (allocates in an APR pool; `apr_pools.h` is always included).
- C qualifiers: `val` and parameters are plain C (eclang enforces immutability).
- `const` (`statement/Constants.kt`, `CompileTimeConstant`): the value must be compile-time (literals, `IRConstantRef`, folded arithmetic). Untyped numbers keep their literal type, so uses fold and adapt. A top-level one is `#define NAME (value)` (`IRDefineConstant`), processed before other globals; a local one is inlined. `defer` runs in reverse order (last deferred first).
