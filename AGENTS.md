# AGENTS.md

eclang ("Easy C Lang"): a systems language compiled to **human-readable C**, aiming for full C interop. The compiler is Kotlin with an ANTLR 4 grammar that uses Python-style indentation (antlr-denter). Experimental; [README.md](README.md) is the language reference. Read it only for syntax questions.

**Goals:** C interop · readable C output · union types, duck typing, interfaces · overloads, functional style · null safety · immutable records by default (`mut rec`) · APR memory pools, `defer`, deep clone · modern syntax (Python/Kotlin/Go/Elixir) · errors as values · production-grade but beginner-friendly (errors explain how to fix them).

If you find any out of scope issues, document them in `KNOWN_ISSUES.md`.

## Build / run / verify
```
mvn clean package                                   # -> target/eclang-0.1.0.jar
tests/run.sh [filter]                               # ect2 + compiler unit tests + `run` + `use "lib:..."` (tests/link) + C binding check + core:term in a pty + tests/pass (compile, gcc -Werror, compare .out; .release.out with --release) + tests/fail-c (rejected by gcc) + tests/doc (`doc`, compare .md/.err) + tests/lib (`lib`, link a C program, compare .out) + tests/panic (expected runtime stop) + tests/tls (`run`, compare .out; only with OpenSSL's headers) + tests/fail (expected error) + `run -m` of tests/memory (AddressSanitizer finds a use of freed memory)
java -jar target/eclang-0.1.0.jar -c examples/fib.ec -o out.c [-d debug dump] [-t time]
gcc -fwrapv -fno-strict-aliasing out.c -o out -I/usr/include/apr-1.0 -L/usr/lib -lapr-1 -lm && ./out
java -jar target/eclang-0.1.0.jar run examples/fib.ec [-k dir] [-r] [-m]   # compile + gcc + run (-r: release, no `debug` statements; -m: --check-memory, a malloc per allocation under AddressSanitizer)
java -jar target/eclang-0.1.0.jar lib tests/lib/geometry.ec [-o dir] [-s] [-k]   # libNAME.so (-s: .a) + NAME.h from `export fn`s; -c file.ec --lib [--header x.h] for the C only
java -jar target/eclang-0.1.0.jar doc examples/fib.ec [-o docs.md]   # Markdown from /** ecdocs */
java -jar target/eclang-0.1.0.jar check   # compiles on request over stdin, for editors (Checker.kt)
```
Always run `tests/run.sh` after a change. Add a `tests/pass/*.ec` + `.out` for new features, a `tests/fail/*.ec` (first line `// error: <expected text>`) for new diagnostics, and a `tests/panic/*.ec` (first line `// panic: <expected text>`) for new runtime checks.

## Pipeline (src/main/kotlin/github/mrh0/eclang/)
0. `Compiler.compile(file)`: one compilation, with its own `CompileData`; it returns the C or the collected errors.
1. `Compiler.tokenizeStream`: ANTLR lexer/parser (the first syntax error becomes an `EcError`, worded by `SyntaxHints`), then `ast/Visitor.kt` maps the parse tree to `T*` tokens (`ast/token/**`).
2. `TProgram.process`: loads `use "*.ec"` files recursively (each declaration remembers its file's module), then works in phases: `const`s that need no declared type → type names → aliases → record/interface fields → function signatures (`cd.functions.declare`) → `const`s → other globals → bodies (`cd.functions.buildAll`, a worklist that also builds generic instances).
3. Each `ITok.process(cd: CompileData, hint: Type): Pair<Type, IIR>` type-checks and lowers in one pass. `hint` is the expected type (`Types.None` = none).
4. IR (`ir/**`) emits C via `toC(CSourceBuilder, Context)`. `IRProgram` renders the code first, then writes includes, runtime prelude, types, atoms, helpers, prototypes, globals, functions and the C `main`.

Key places:
- `doc/`: ecdocs (`/** */`, Javadoc-style tags). The lexer sets them aside; `DocExtractor` attaches them to declarations (`Compiler.parse` → `TProgram.docs`), and `Markdown` renders them for `eclang doc`.
- `ect2/`: the type system. `TypeContext` has interned types, `cost(from, to)` (0 = fits, 1+ = lossless conversion, NO), `explain`, `storageProblem`, `resolve`, `bind`/`substitute`.
- `output/c/CTypes.kt`: the C representation of every type, plus generated typedefs and helpers.
- `context/`: `CompileData` (`expect`/`storable`/`usable` checks, modules and name lookup, hoisting, loops), `function/Functions.kt` (overloads, calls, generics), `Narrowing.kt` (flow typing), `ContextStack` (scopes, defers, narrowing), `Module.kt`.
- `bindings/`: bindings of C libraries outside `core:`. `bindings/raylib/raylib.ec` is generated by `generate.py` there (edit its tables, not the `.ec`); `tests/run.sh` checks it only when `raylib.h` of the same version is installed or on `C_INCLUDE_PATH`. `bindings/ffmpeg` (FFmpeg 8) is written by hand, one file per library, except `constants.ec`, which its `generate.py` makes from the headers; `tests/run.sh` checks it and runs its examples when FFmpeg's headers of the same major versions are found. `bindings/sqlite` is written by hand too, with `constants.ec` from its `generate.py`. `bindings/cimgui/cimgui.ec` (Dear ImGui) is generated by `generate.py` there from a cimgui checkout's JSON metadata, so edit its rules and tables, not the `.ec`. Its fields are checked by `tools/check-bindings.py --fields`. It needs `use "define:CIMGUI_DEFINE_ENUMS_AND_STRUCTS"` (`TGlobalUse`, `IRDefine`: a `#define` before every `#include`). Defaults of a `declare fn` are passed at the call, through `Overload.full`/`callerFilled` like `caller`.
- `src/main/resources/`: the `core:` stdlib (no prelude): `string.ec`, `errors.ec`, `array.ec` and the data structures (top level, so their functions work as methods from any module; `Error` is in `errors.ec`): `list.ec`, `map.ec` (also the `hash` overloads), `set.ec`, `deque.ec`, `heap.ec`, `slotpool.ec`, `tree.ec` (SortedMap, SortedSet), `bitset.ec`, `lru.ec`, and `structures.ec`, which only `use`s them all, the modules `math.ec`, `io.ec` (`io.log`), `time.ec`, `thread.ec`, `os.ec`, `term.ec`, `encoding.ec`, `net.ec`, `fs.ec`, `json.ec`, `hash.ec`, `args.ec`, `unicode.ec`, `bytes.ec`, `csv.ec`, `env.ec`, `log.ec`, `regex.ec`, `http.ec`, `test.ec`, `bench.ec`, `path.ec`, `uuid.ec`, `big.ec`, `tls.ec`, `parallel.ec`, binding files, one per C header (`c/*.ec`), per APR header (`apr/*.ec`) and for OpenSSL (`openssl/ssl.ec`), and bundled C with its bindings (`vendor/`). `tools/check-bindings.py` checks every `declare fn` of them against its C header (`tests/run.sh` runs it on all of them; on `tls.ec` and `openssl/` only when OpenSSL's headers are found, as it does `tests/tls`).

Details: [docs/architecture.md](docs/architecture.md). Recipes for adding syntax, types or IR: [docs/howto.md](docs/howto.md).

## Gotchas
- **Grammar edits:** the code uses the **checked-in** parser in `src/main/java/github/mrh0/eclang/antlr/`. Maven's own ANTLR output has no package and is unused. Run `tools/regen-parser.sh` after editing `Eclang.g4`. In `expr`, alternatives listed first bind tightest (precedence).
- **VS Code extension (`ls/vscode`):** its language server is a TypeScript port of the front end (grammar, `SyntaxHints`, `doc/`). After changing those, run `npm run gen` there if the grammar changed, update the port, and run `npm test` there: it compares the port with the compiler jar. See [ls/vscode/README.md](ls/vscode/README.md).
- **Type checks go through `CompileData`:** use `cd.expect(loc, value, type, what)` to convert a value to a type (it returns the IR with the conversion), `cd.storable` for variable, field and return types, and `cd.usable` to reject `None` and unhandled `Result`s. Error text should say how to fix the problem; reuse `types.explain`.
- **Union parameters split a function into per-type copies** (`Overload.isUnionCopy`). In those copies `is`/`== null` checks may be constant: `Narrowing.constant` skips the dead branch, and "always false" errors are suppressed.
- **Generics:** `<T>` functions (`Overload.isTemplate`, also for a `<T>` only in the result or a variadic) get a copy per call (`Functions.instantiate`). `rec List<T>` is a `GenericRecord`; each `List<Int>` is an ordinary `Record` made by `TTypeRecord.instantiate`, so the back end needs nothing for it. `List<T>` in a signature is an `Applied` type until `bind`/`substitute` resolve it. A call's expected type decides a `<T>` only the result has (`Functions.call`'s `expected`); lambdas without parameter or return types are compiled after the other arguments (`Functions.lambdaHint`, `TLambda.wantsExpectedType`).
- **`>>` is two `>` tokens** in the grammar (`shr` in `exprBinOp`), so `List<List<Int>>` closes; the Visitor checks they touch. The record-literal alternatives of `expr` come before `NAME`, or `Box<Int> { 1 }` parses as a comparison.
- **Evaluation order:** C doesn't sequence arguments or operands, and gcc runs arguments right to left, so a new form with several values in one C expression compiles them through `ArgumentOrder` (`compile`, `finish`, `wrap`; `inOrder` for a list; `operands` in `Ops.kt` for two sides). `wrap` can make a literal a comma expression, so don't take its address or match on its IR class (`TAddressOf`). The initialiser of a global gets its temporaries from `cd.withGlobalTemps`, in the C `main`. A new way of calling something must `cd.noteEffect()`, or the values around it aren't kept in order.
- **Hoisting:** `try`, `??` on a `Result`, `?? ret` and `when` as a value run before the current statement (`cd.hoist`). Code that runs conditionally or repeatedly wraps itself in `cd.noHoist(reason)`. A value read twice that must work there too declares a temporary with `cd.declareTemp` and sets it in place (`IRTempSet`).
- **Iteration:** `for x in v` on anything but an array or String calls `next(@X)` (a type is its own iterator) or `iter(v)`; `for a, b in v` tries `pairs(v)` first. See `TStatementForeachIn.loopOver` and `Functions.protocolCall`.
- **Statements ending in a value** take `tail`, not `expr NL`: a `when` or a `try ... catch e do` block (`TTryCatchExpr`) ends with a DEDENT, after which the denter gives no NL.
- **Never:** a new statement form that evaluates a call must `setReturned` on a `Types.Never` value (`TStatement`, `TStatementCall`), or flow typing and the missing-`ret` check won't see that it leaves.
- **Global initial values:** `Functions.initializationOrder` sets a global after those its value needs, following `uses`, which also holds globals (`useGlobal`, from `findVar` and `getVarIn`). A new way to reach a global must go through those.
- **Exits of a scope** run deferred statements through `cd.compileDeferred`, with `TErrDefer.normal` unless the exit is an error.
- **`distinct` types:** code that needs a `Prim` goes through `Ops.base`, because `Ops.isNumeric` and `isInteger` are also true for a `Distinct`.
- **Modules:** run code of a module inside `cd.inModule(m)`. Unqualified names resolve in the current module, then the top level (`cd.findVar`, `Functions.visible`, `TypeContext.lookup`); `x.name` with `x` a module (and not a variable) is a qualified name. C names come from `Module.cName`/`Declared.cName` (`geo__make_0`); global C names are reserved with `cd.claimCName` (a name the C headers already use gets the `__ec_v_` prefix: `src/main/resources/c-reserved.txt` lists those of every program and `c-reserved-headers.txt` what each `core:` header adds for the programs that `use` it, both from `tools/gen-c-reserved.py`, which must run again after a binding starts using a new header). Locals and parameters take their C name from `cd.localCName`, which adds that prefix when the name would hide a file-scope C name.
- **Completion** (`Completion.kt`, `eclang check`'s `complete` request, for ls/vscode): the word at the cursor becomes `Completion.PROBE`, and the tokens that read a name (`TNamed`, `TAccessorNamed`, `TExprCall`, `TTypeByName`) call `Completion.name`/`member`/`module`/`type` when they meet it, which list what fits from the live `cd` (`visibleLocals`, `Functions.visibleOverloads`/`methodsFor`, `TypeContext.namedIn`, the `hint`) and throw `Completion.Hit`. A new token that resolves a name written in the source should do the same.
- **Errors are collected:** `cd.report`/`cd.recover` record an `EcError` and go on, per declaration (`TProgram`), per function body (`buildAll`) and per statement (`TBlock`, which unwinds the scopes; only calls, assignments and unconditional `ret` let the rest of the block be checked). `cd.checkpoint()` stops between phases with errors (`EcAbort`). After an error, `cd.functionHasErrors` turns off the unreachable-code and missing-`ret` checks for that function. `cd.warn` adds warnings.
- **Pools and lifetimes:** allocation goes through the current pool (`__ec_pool`, `pool` in eclang) or an explicit `Pool`; see `TStatementPool`, `TNew`, `Builtins`. Every expression token says what its value may point into with `pointerFlow()` (`PointerFlow.From(...)`, or `Nothing` for numbers, Bools and literals); it has no default, so Kotlin rejects a token that doesn't. Statements, declarations and types extend `NonValueTok`. A form that allocates must also be added to `Lifetimes.value`/`allocations`, or the dangling-pointer and freed-pool checks won't see it. If it allocates in the current pool, it must also call `cd.noteAllocation` (or use `Builtins.current(cd, ...)`), for the pool the compiler gives a loop's rounds when nothing a round allocates outlives it (`LoopPools`: each `Lifetimes.followed` step also runs `imagining` a pool per round, and `decide` enables `IRRound`/`RoundLeave`, which write nothing otherwise; see [docs/architecture.md](docs/architecture.md)). A new way out of a round must run the deferred statements of the loop body's scope, where `RoundLeave` is. A new form that passes on memory out of the function without `ret`/`throw` (as `try` does) must copy it into `cd.entryPool`, which is decided when the C is written. A call's result is assumed to point into its arguments (`TExprCall.aliased`), numbers and Bools aside, except those its body never returns into (`Escapes.resultRoots`, known only when `Compiler` compiles again after an `EcMemoryError`: errors of `Lifetimes`/`Escapes` throw that type). A new way to give a value to the caller must call `Lifetimes.noteResult` (`ret`, `throw` and `try` do), or a summary will miss it. A new statement that binds a name to a value must call `Lifetimes.define`. Generated allocations call `__ec_palloc`, not `apr_palloc`.
- **Literals in a `when` value:** its arms are C blocks, narrower than the eclang scope `Lifetimes` gives what they contain, and a C compound literal dies with its block. While `cd.keepingLiterals` is active, array literals and `addrof` of a literal use `cd.literalStorage`, a variable declared before the statement. A new form that makes a pointer to a compound literal must do the same.
- **Freed pools:** `ContextStack.Scope` tracks, per scope, which named pool each variable's value was allocated in (`Alloc`) and the last `clearPool`/`destroy` of each pool (`Kill`); `TNamed` calls `Lifetimes.checkAlive`. Its `allocations` also has keys starting with `@` (`@o.name`, `@a[...]`), which are places behind a parameter, not variables (`storeBehindParameter`). A pool has an identity (`Lifetimes.poolId`), shared by its aliases and `Pool` fields. A scope's knowledge joins its parent's in `pop` unless it left early (`ContextStack.join`: per path, memory no path that holds it freed is moved after every kill so far); a block's own scope replaces it (`pop(ran = true)`, `TBlock`), and `TStatementIf` joins its branch ends without the pre-`if` state (`popBranch`, `joinBranches`). A way out that doesn't end the scope compiles its deferred statements in `ContextStack.onExit`. A loop's later rounds are checked through `LoopRound` (carried `Alloc`s), not by killing pools at its start. `clearPool` and `destroy` (`TStatementDestroy`) need `unsafe` unless the function made the pool (`Lifetimes.owns`: `ContextStack.ownedPools`, filled by `trackPools` for `new Pool`, `TNew.makesPool`) or took it over (`own p: Pool`, `TParameterOwn`; the caller's `Lifetimes.giveAway` kills it). A `defer` inside `unsafe` stays unsafe (`TUnsafe.keep`).
- **Lifetimes through calls:** what a function stores of its arguments is an `Escapes.Store`, recorded by `Lifetimes.assign` and checked at each call after all bodies are compiled (`Escapes.check`). A new way to store a value must go through `Lifetimes.assign`, a new way to call an eclang function through `Lifetimes.noteCall`, and a new value token that allocates must be added to `Lifetimes.sources` as well as `value`. A store through a call's result writes into the arguments in its `storedInto` (`Lifetimes.storedInto`: those whose type reaches what the result points at). An `escaping` parameter (`TParameterEscaping`, `Parameter.isEscaping`) is a `Store` into a global with `escaping = true`; `Lifetimes.checkEscaping` checks C functions' and owned pools at the call. A `kept` parameter of a `declare fn` (`TParameterKept`) is a `Store` into its other pointer parameters, under the `Overload`. A lambda is followed like a function (`Closure.escapeParams`: its parameters and `^x` per capture) and checked where it is written (`Lifetimes.noteLambda`). What a function value keeps in its arguments is followed by its `FunctionType` (`Escapes.addToType`, `Lifetimes.noteValueCall`); a lambda or `fn name` that keeps its parameters anywhere else is an error. A new way to call a function value must go through `noteValueCall`.
- **Lifetimes in loops:** a body is compiled once. New steps that follow local memory go through `Lifetimes.followed`, which runs them again after the loop (as deep in `unsafe` as they were: `Replay.unsafeDepth`), so they must do nothing else; state they read from `cd` must be restored by `replay` too; pools use `LoopRound` instead. See [docs/architecture.md](docs/architecture.md).
- **`mut` parameters:** `mut p: T` is a `Parameter` with `isMut` and the type `@T` (`TParameterMut`; `out` sets `isOut`, `declare fn` only). The Visitor turns each `p` of the body into `TReadPointer(p, mutParameter = true)` (`withMutParameters`, not inside lambdas, also in `${...}`), so assignments, `Lifetimes` and freed-pool checks see a write through a pointer parameter. `Lifetimes.place` counts `addrof p` as local memory (not for a store's target: that is the caller's). Narrowing keeps facts about it under `@p` (`ContextStack.narrowedType`, `Narrowing.local`), and the Visitor records `@p` and `mut x` like assignments for loops. At the call, `TMutArg`/`MutPlace.address` gives `@T`; `Functions.score` matches it only to a `mut` parameter of exactly that type (`mutCost`), and `mutProblem` explains a miss. `x.f()` passes `&x` when `Functions.receiverByAddress` says so, decided from declared types (`MutPlace.typeOf`) before x is compiled, so ArgumentOrder never keeps a copy of x. After the call, `TExprCall.followChanges` rejects one variable given twice and has `Lifetimes.assign` follow what the call may have stored; `cd.changedByCalls` stops ArgumentOrder taking those locals as fixed.
- **`ref rec`:** `Layout.isRef` (and `GenericRecord.isRef`). In a type (`TTypeByName`, `TTypeApplied`, `TTypeArgument`, `new T[n]`) the name means `@Record` (`refType`), which prints as the name (`Pointer.toString`); a record literal, `new Name` and `extends` mean the record. A literal of one must be inside `new` (`TCreateRecordTyped.inNew`) unless the record itself is expected (`@c = Counter { ... }`).
- **Narrowing and `addrof`:** the Visitor records the locals whose address a function takes (`TFunc.addressTaken` → `cd.addressTaken`); `Narrowing` doesn't narrow them, because a write through the pointer could undo the check.
- **Record fields in C:** a child record holds its parent as its first member (`d.Animal.legs`), so C code naming a field, its type tag or `offsetof` goes through `CTypes.fieldPath`/`tagPath` (or `member`, `readField`), never `.$name`.
- **`T[N]`:** a struct `__ec_fixed_Int_4` everywhere except as a record field or C global, which is a C array read through a cast (`readField`, `IRFixedStorage`, `CTypes.member`); code reading record fields in C must use those. It converts to nothing implicitly, so that `a[..]` and `.data` are tokens `Lifetimes` can see (`viewsValue`).
- **Contextual words:** a word that means something in one position only isn't a keyword: the grammar takes a `NAME` there and the Visitor checks the word (`packed`, `align`, `union`, `struct`, `export`, `extern` (`externName`), `module`, `where`, `requires`/`ensures`/`debug` (`contracts`), `distinct`, `pool`, `debug`, `out`, ...). `it` is `TIt` in a `|>` stage (`visitExprNamed`), an ordinary name elsewhere; `here` and `pool` are `TNamed` falling back to `THere` and the current pool when no variable has the name (`TNamed.isHere`, `isCurrentPool`). A `NAME expr` contract is ambiguous with `debug NAME expr`: the grammar lists the plain one first, and `Visitor.contracts` parses `debug requires x - 1 > 0`, which ANTLR then splits in two, again (`reparseContract`). `primitive` comes before `primitive NAME` in `expr` for the same reason (`requires n > 0 ensures -r`). `Omit<R, :a>` (an atom union without some atoms) is `TTypeApplied.omit`, used only when no type is called `Omit`. `Volatile<T>` isn't a type either: the Visitor takes it off a `var`'s declared type (`varType`) and rejects it anywhere else.
- **Layout:** Code that takes a field's address must respect `TAccessorNamed.bitFieldOf` and `inPacked`/`alignedAnywhere`. A C `union` is a `Record` with `isUnion`; it has no `==`, and `clone` and `${...}` don't look inside it.
- **Libraries:** with `cd.library`, non-exported C functions are `static` (`CTypes.isHidden`) and a prototype written by hand must say so too; see `callPrinter`.
- **Printing and hashing:** `${x}` of a record or tuple is `IRShow` → `CTypes.show`, built from `format` helpers; `Functions.resolvePrinters` runs at each `${...}` to find the `str` overrides of everything the value holds and `use` them (a helper can't do that, the back end runs after culling). A `str` is looked up in the type's own module and the top level only, so `Functions.printers` can hold one per type. `hash` is a builtin that also applies when no `hash` overload takes the argument (`TExprCall.callFunction`), and takes exactly what `equalityProblem` allows: a type `==` learns to compare must be added to `CTypes.hashed`, and hashing must stay field by field (padding) and agree with `equals` (`0.0 == -0.0`).
- **Running out of stack:** `PROGRAM_RUNTIME` in `IRProgram` catches the fault on a signal stack. `signal.h` and `sys/resource.h` are in every program, so their names are in `c-reserved.txt`; `unistd.h` isn't, so `write` is reached through an `__asm__` name.
- **Assertions:** `assert`, `requires` and `ensures` go through `Assertions.compile`, whose report is only built on the failure path (no `noteAllocation`); the Visitor records the text of a condition's tokens (`withSources`). A new operator worth showing in reports goes in `Assertions.operands`/`rebuild`, and a new constant IR in `ir/ConstFold`. `const assert` is `TConstAssert`; `sizeof` & co. become `_Static_assert`, which only gcc checks (`tests/fail-c`).
- **`debug`:** `debug stmt`/`debug do` (`TDebug`) is an `if (__EC_DEBUG)` with a condition the compiler treats as unknown, so it is checked the same in a release build (`--release`, `cd.release`); a new statement needs nothing for it. `debug` isn't a keyword (`log.debug`): `statementPrefixed` is `NAME statement`, last in `statement`, and the Visitor rejects other words. `debug defer x` must stay `defer (debug x)`.
- **Contracts:** a function with `requires` takes the call site first thing (`IRTakeCallSite`); direct calls go through `Functions.contractCall`'s `_at` wrapper, so a new way of calling an eclang function directly should too (`callIR`). Overloads with the same parameter types told apart by (non-`debug`) `requires` share an `Overload.dispatch` list (guarded first, the unguarded fallback last); a call goes to `dispatchHead`, whose body starts with `if not cond do ret next(params)` per conjunct (`Functions.build`, `Forward`, `forwardTo`, passing `__ec_at` on), so a new way of picking an overload must go through `dispatchHead`. `ensures` are checked in `TStatementReturn` and at the end of a None function (`Functions.ensures`), so a new way to return from a function must call it.
- **`unsafe`:** `unsafe expr` and `unsafe do` (`TUnsafe`) raise `cd.unsafeDepth` (reset per function in `Functions.build`). An operation the compiler can't check is an error unless `cd.isUnsafe`: so far `new (<T>)[n]` in a generic function (`TNew.array`), and `[]` on a pointer or C array (`TAccessor.checkUnbounded`; `p[0]` is allowed). The Visitor turns `unsafe x[i] = v`, which parses with `unsafe x[i]` as the target, into `unsafe` around the assignment.
- **Runtime checks:** `/`, `%` and shifts by a computed count become `IRCheckedArith` (`RuntimeChecks.needed`, `CTypes.checkedArith`); `--overflow-check` adds `+ - *`. Pointer results of `declare fn` and reads of pointer fields of C structs (`Record.isExternal`) are wrapped in `IRCNotNull`. `.data` of a String or `T[]` goes through `IRArrayData`, which is never NULL; it is a `Char[]c` for text, not a `CString` (`cstr` copies and adds the 0). A value stored in a bit-field goes through `fitBits` (`IRCheckedBits`; `IRBitFieldCompound` for `op=`), so a new way to store into a field must too. A String converts to a `Char[N]` (cost 1) through a helper that checks its length (`CTypes.stringToFixed`). Panics flush stdout first.
- No global state: types, modules and atoms (`cd.atoms`) are per `CompileData`, so one JVM can compile many times (`CompilerTest.kt`).
- **Default values:** a parameter left out is a local set at the top of that copy of the function (`Functions` build step), so its default runs once. `Lifetimes.define` still sees the default. `at: Location = caller` (`Parameter.isCaller`, `caller` is a name, not a keyword) instead makes an overload without it whose `full` is the one with it; `Functions.call` redirects to `full` and inserts `THere.value` of the call. `here` is `THere`. `Location` is a top-level record of `core:errors.ec`.
- **`mut rec`:** records are immutable by default; `Layout.isMut` (written `mut rec`, `mut ref rec`, `mut union`; `mut` is a `recordModifier`; for C typedefs `declare mut rec`/`declare mut union rec`) and `Record.isMutable`, also true of `declare struct`/`declare union` (`isCStruct`, always mutable for C compatibility). A `declare rec` is fixed unless declared `mut`; `fixedRecord` lets an opaque one (no fields) fit `<mut T>`. Every field write goes through `TAccessorNamed.place`, whose `readOnly` is `fixedField(...)` for a record that isn't mutable, and `@c = ...` of a `ref rec` through `TReadPointer.place`; a new way to write a field must go through a `place`. A `mut rec` can't extend a fixed one (`TTypeRecord.declareType`). `<mut T>` (`TTypeGeneric.isMut`, collected into `cd.mutTypeParams` while `Functions.declare` compiles the signature, then `Overload.mutGenerics`) and `rec Box<mut T>` (`GenericRecord.mutParams`, `checkMutArguments`) reject types for which `TypeContext.fixedRecord` is non-null.
- **`resource rec`:** `Layout.isResource`. `TStatement`/`TStatementCall` reject dropping one; `Lifetimes.define` notes locals holding one in `cd.unusedResources`, `TNamed.process` removes them, and `Functions.build` reports what is left.
- **Threads (`Sharing`):** a `flat` parameter (`TParameterFlat`, `Parameter.isFlat`: `thread.spawn`'s data and body, `thread.Queue`'s items) takes only values that reach no memory but `sync` records (`Layout.isSync`, `sync rec`, not checked inside); `Sharing.checkArgument` runs in `TExprCall.noteCall`, and looks at what a lambda captures (`TLambda.captures`).
- **Unions:** reading a field of a `union` that can hold a pointer needs `unsafe` (`TAccessorNamed.pointerOfUnion`, `checkUnionRead`, also where a place reads it: `TAccessor.place`).
- **Linking:** `use "lib:z"` (`TGlobalUse.link`) adds to `cd.linkedLibraries`, which `run` and `lib` turn into `-l` flags. The name is checked because it reaches the C compiler's command line.
- **Closures:** a function value is a pointer to a closure struct whose first member is the C function (`f->call(f, x)`, `IRCallValue`); only a function type of a `declare` or `export fn` is a plain C function pointer (`FunctionType.isC`, `TypeContext.inC`), which only `fn name` and a lambda that captures nothing convert to. A lambda captures through `cd.findVar` (`CompileData.capture`): `val`s and parameters by copy, `var`s by pointer, into a closure allocated in the current pool; `TLambda.captured` gives Lifetimes `x`/`addrof x` per capture. A new kind of local (an `IVar`) must work when captured: by copy unless `canAssign()`. `try` in a lambda goes through `cd.closure` (`Closure`). See [docs/architecture.md](docs/architecture.md).
- **Culling:** `Functions.use` records which C functions each function (or lambda, or global code) uses; `reachable` keeps only those reachable from `main`, globals and `export fn`s. A new way of referring to a function must call `use`, or its C function is left out.
- Generated C must compile with `-Wall -Wextra -Werror` except unused locals: a parameter the C body never mentions gets `(void)p;` (`IRFunctionOverride`).
- Identifiers that are C keywords get a `_` prefix (`Util.testIdentifier`). The `__ec_` prefix is reserved for generated code, and `__` separates a module from a name in C.
- eclang has no `const`: calls of `declare fn` functions cast pointer-to-pointer and function-pointer arguments to `void*`, and pointer results to eclang's type (`Functions.constSensitive`, `IRCCast`).
- `out`, `out.c` and `target/` (including `.kt` copies) are tracked in git. They are build artifacts, so don't hand-edit them; `mvn clean` deletes the tracked `target/` files.
- **`core:thread.ec`:** uses `pthread_create`, not `apr_thread_create`, whose handle stays in the given pool, so a detached thread would outlive it. What a thread starts with is `malloc`ed for that reason. The C `main` doesn't call `apr_terminate`, which would free the allocator under a detached thread.
- **`core:term.ec`:** what restores the terminal runs in signal handlers, so it uses `write`, not `emit`/APR, and allocates nothing (`undoModes`); `tests/term-pty.py` drives it in a real pseudo-terminal.
- **Bundled C:** `use "core:vendor/x.c"` writes the file into the generated C (`IREmbed`), because a program can't link other libraries. It shares that file with the program's names, so everything in it is `static` and starts with `__ec_`, and it `#undef`s its macros; see [src/main/resources/vendor/README.md](src/main/resources/vendor/README.md).
- **`core:net.ec`:** `apr_socket_accept` ignores a socket's timeout, so `net.accept` waits with `apr_poll`. `apr_socket_recvfrom` is given an `apr_sockaddr_t` without a pool, so read it with `apr_sockaddr_ip_getbuf`, not `apr_sockaddr_ip_get`. A `Connection` knows its pool (`mem`), and reads and writes go through `receive`/`sendSome`, which use its `Transport` when it has one (TLS): a new way to read or write the socket must too. `readMore` and `handshake` never wait: they set the socket's timeout to 0 and put it back. A `Poller`'s token is the `client_data` pointer (`token as unsafe @Any`).
- **`core:tls.ec`:** net and http don't depend on OpenSSL: `tls.ec`'s global `installed` sets `net.tlsClient` when the program starts, so `use "core:tls.ec"` is what turns TLS on, and `net.requireTls` explains what to add without it. OpenSSL reads and writes through a BIO of our own (`bioRead`/`bioWrite`) over `apr_socket_recv`/`send`, so the connection's timeout holds, and an EAGAIN becomes `SSL_ERROR_WANT_*`. The `Session` and the `SSL` live in the connection's pool (a cleanup frees the SSL). The client context with the system's certificates is made once, under `clientLock`.
- **`core:regex.ec`:** a Pike VM, so there is no backtracking anywhere: `compile` must stay bounded too, by `MAX_PROGRAM`, `MAX_SLOTS` and the `work` count (repeats of empty groups add no instructions), and `addThread` keeps an explicit stack so that a long pattern can't overflow the C stack. A loop around something nullable compiles as `(x+)?` (`emitStar`). Fuzz changes against Python's `re`: everything agrees except loops around something nullable.
- **`core:http.ec`:** one dispatcher thread (`dispatch`, `round`) owns the `Poller`, accepts every connection into a pool of its own (`new Pool in d.base`, made and destroyed only by the dispatcher, as APR pools aren't thread-safe), does the TLS handshake, and reads with `net.readMore` until a request's head is there (`hasHead`) or the buffer is full. Then it hands the `Client` to a worker through the `ready` channel; the worker gives it back through `done` and wakes the poller. The calls that keep Clients in the dispatcher are `unsafe`: the compiler can't follow pools through channels. On `stop` the dispatcher closes `ready` and waits for every Client out with a worker before freeing anything.
