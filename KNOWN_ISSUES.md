- **C fields named like an eclang keyword can't be declared.** `declare rec` has no way to give a field another C name, so `apr_proc_t.in` can't be declared (`in` is a keyword). `core:os.ec` casts to a record of the same layout (`ProcessFields`) as a workaround.
- **`c-reserved.txt` doesn't know every bound header.** A top-level `val` or `fn` named like something in `unistd.h`, `signal.h`, `time.h` or another header only some programs include can break the C build. `termios.h` and `sys/ioctl.h` are listed; listing `unistd.h` would rename common names (`close`, `read`) in every program, so the real fix is to reserve names per included header.
- **`core:term.ec` keeps at most 64 KB of stderr in full-screen mode.** More than that is written to the screen when the buffer fills.
- **`core:term.ec` only sees one code point per cell.** Combining marks are dropped from a `Screen`, and emoji sequences (flags, skin tones) are measured one code point at a time.
- **A string can't initialise a `Char[N]`.** `name: Char[16]` needs an array literal, or `strncpy(r.name.data, ...)`.
- **A value too large for a bit-field is cut to its width without a check,** as in C. Only literals are checked.
- **Layout gaps:** no `align(n)` on a single field, no unnamed padding bit-fields (use a named field), no zero-width bit-fields, no flexible array members (`char data[]`), and no generic `union`.
- **A library's per-thread pool lives until the library is unloaded,** even after the thread ends, unless that thread calls `NAME_clear()` first. `export` works on functions only, not on globals.
- **An interface only sees functions of the current module and the top level.** `Functions.missingMethod` uses `visible(name)`, so `io.File` doesn't fit `inter Closer` with `fn close()` outside module `io`, although `io.close(File)` exists. For the same reason, `f.close()` doesn't work outside the module either.
- **A program can't ask to link a C library.** `run` and `lib` pass only the APR flags and `-lm`, and no option or `.ec` declaration adds others, so a `core:` binding to anything else (sqlite3, zlib) can't be built by `eclang run`.
- **`apr_socket_recv` takes its buffer as a `CString`.** A `new Char[n]` buffer needs `buf.data !as CString`, and `cstr(s)` looks like the obvious way but received nothing into `s`. `core:net.ec` hides this.
- **A `"` inside `${...}` is reported in the wrong place.** `"a ${f("x")} b"` isn't allowed, which is fine, but the syntax error points at an earlier line: the `else` before the string, if there is one, or the argument list. Use a variable for the inner text.
- **`core:net.ec` can't wait for several sockets at once.** `waitReadable` takes one, so a server gives each client a thread. APR's pollset is bound in `core:apr/poll.ec`, but has no wrapper yet. There is no TLS either: that needs a library that can be linked, or bundled.
- **`core:json.ec` gives up on a lone surrogate (`"\ud83d"`).** It is an error, where some parsers put U+FFFD in its place.
- **`clone` tells copies apart by address only.** `__ec_clone_enter` ignores the type, so with `first: @Inner` pointing at the first field of `second: @Outer`, `second` gets the small Inner copy, and writing to `copy.second.b` overwrites whatever comes next in the pool.
- **Lifetimes stop at function calls.** A callee can store what it is given (`fn keep(p: @Int) do g = p`, with `keep(addrof x)` in the caller), or something it allocated in its caller's pool (`g = new 1`, or `r.name = "${n}"`, called inside a `pool do`), and nothing notices. `l.push("${i}")` in a `pool do` is the common case: core:structures.ec documents it, the compiler doesn't reject it. A `Pool` parameter hides `clearPool`/`freePool` the same way: `fn drop(p: Pool)` called with `pool` frees the current pool, and after `drop(p)` the caller can still use what was in p. A callee's write through a pointer isn't seen either: `set(addrof o, addrof x)` with `fn set(pp: @@Int, v: @Int) do @pp = v`, then `ret o`.
- **A deferred free doesn't look through calls at `ret`.** With `defer freePool(p)`, `ret s` of something in p is an error, but `ret id(s)` isn't. A call's result only may point into its arguments, and treating that as certain rejects the usual scratch pool (`core:regex.ec`: `ret matchOf(m)`, whose result is in the current pool). `Alloc.viaCall` marks these. An explicit `val r = id(s)`, `freePool(p)`, then using r, is rejected, so the two differ.
- **A deferred free run by `break` isn't seen after the loop.** A scope that always leaves passes on nothing, so `s = format(p, ...)`, with `defer freePool(p)` and `break` in the body, leaves s usable after the loop.
- **A pool's memory stored behind a pointer parameter isn't checked when the pool is freed.** `o.s = format(p, ...)`, then `freePool(p)`, leaves the caller's record dangling. `Lifetimes.kill` only does this check for globals, and a global only sees what the same function did to it.
- **What is known about pools merges without its path.** After `if c do` with `clearPool(p)` and `s = format(p, ...)`, an `s` that was in p before is rejected, although on the path where p was cleared s has a new value. A use of s in a loop is rejected the same way when two branches of the body do those two things. Give s a new value on both paths.
- **A variable's local memory is never forgotten.** `var p: @Int = addrof x`, `p = addrof g`, `ret p` is rejected, as `setOrigin` only adds to what p may point into. In a loop, all of a variable's assignments reach every use, unless it is defined in the loop.
- **Threads aren't checked at all.** `thread.spawn(fn work, addrof(a))` needs no `join` before a's block ends. A thread's pool is freed when it ends, so a global or `Channel` item allocated there dangles. Sharing a `@List` between threads compiles and races. A `spawn` and `detach` in a `pool do` crashes at exit in `apr_pool_terminate`.
- **Memory-unsafe operations need no `unsafe` or `!as`.** `p[100000]` on a `@T`, `a.data[i]`, `addrof x!` on a null pointer, and reading a pointer field of a C `union` holding something else. `.data` of a slice or a `Char[N]` is a `CString` with no 0 at its end, so `strlen`, `io.log` and `clone` read past it. `.data` of an empty array is NULL, and `Mapped.text` is left dangling by `fs.unmap`.
- **A non-null value can still be null.** `new (<T>)[n]` returned from a generic function gives a `(@Int)[]` of NULLs. A function called by a global's initialiser can read a later global that isn't set yet (`val a: Int = f()` before `val b: @Int = new 1`). The `IRCNotNull` check only covers a `declare fn`'s result, not fields of C structs or arguments of C callbacks.
- **Stack exhaustion is a plain segfault.** Deep recursion and large `T[N]` locals (`var a: Int[100000000]`) have no check or message.
- **A default value is copied into the function, where a comparison with it can fail under `-Wextra -Werror`.** With `fn f(s: String, from: Size = 0)`, `ret null if from > s.len` makes the copy without `from` say `0 > s.len`, which gcc rejects as always false (`-Wtype-limits`). Comparing in a function that takes it as an ordinary parameter works.
- **`core:test.ec` can't find tests or name the line of a failed check.** Tests are listed by hand with `test.run`, and a failure says "check 3" and the `what` it was given. Both need compiler support: a way to list the functions of a file, and something like `__LINE__` for the caller.
- **`core:regex.ec` has no Unicode tables.** `\p{L}` is an error, and `ignoreCase`, `\w`, `\d` and `\b` only know ASCII. A loop around something that can match nothing, as in `(\b|a)+`, may go round once more or less than in Perl or Python, as in Go and RE2.
- **`core:http.ec` holds everything in memory.** Bodies can't be streamed, in either direction. The client opens a connection for each request, and has no cookies or compression.
- **The server of `core:http.ec` has a fixed number of workers.** A client that keeps a connection idle holds a worker until `idleTimeout`, and one that sends a byte now and then holds it until `timeout` passes between reads, so a few slow clients can make the others wait. It wants waiting on many sockets at once, which `core:net.ec` doesn't have yet.
- **`try f() catch e do` discards the value of `f`.** There is no way to get the value and handle the error in one statement, so `core:http.ec` has a function that stores it in a record (`Slot`). The block form is commented out in the grammar.
- **A call that returns nothing can't take `??` as a statement.** `thread.join(t) ?? panic("x")` says "Syntax error at the end of the line", which doesn't point at the reason; `try thread.join(t) catch e do` works.
- **A child record and its parent are unrelated structs in C, so a write through one may not be seen through the other at `-O2`.** With `val k = clone(Kennel { animal = d, dog = d })` (`@Animal` and `@Dog` to one `Dog`), `k.dog.legs = 3` then `k.animal.legs` printed the old value at `-O2`, although the two pointers are equal, and the new one with `-fno-strict-aliasing`. Simpler programs without `clone` didn't show it, but they break the same C rule. The likely fix is to embed the parent as the child's first member. `run` and `lib` pass `-fno-strict-aliasing`, which hides it, and so must anyone compiling the C by hand with `-O2`.
